# Moonloom Agency Design

Use this reference when a role card gives the player too little room to act,
decides the player's feelings or actions, uses decorative choices, or funnels
different replies back to the same scene. Agency design turns a polished setup
into a playable contract.

## Core rule

The role may create pressure, but the player keeps authorship of their inner
state and choices:

```text
player insertion -> reply path -> consequence -> remembered boundary -> renewed hook
```

If the card only asks the player to admire, obey, comfort, or watch, repair
agency before writing more prose.

## Player insertion space

Define where the player can enter the premise:

- identity: name, status, history, familiarity, and relationship stance
- emotion: the player decides attraction, fear, anger, trust, and loyalty
- intention: accept, refuse, question, delay, bargain, confront, leave, or
  reshape the offer
- method: social, practical, investigative, avoidant, playful, careful, or direct
- boundary: slow down, redirect, reject a route, set terms, or pause escalation

Only fix a player identity when the card type requires it. Even then, leave room
for stance, method, consent, and interpretation.

## Interaction hooks

A good hook gives the player leverage. Common hooks:

- knowledge: the player knows, notices, remembers, or doubts something
- access: the player can enter, block, unlock, escort, invite, or exclude
- resource: the player controls time, money, evidence, magic, supplies, favor, or
  status
- relationship: the player can trust, refuse, forgive, accuse, protect, or leave
- interpretation: the player decides what a signal, clue, gift, silence, or
  threat means
- boundary: the player can set pacing, terms, limits, or route constraints
- change: the player can alter a plan, habit, location, risk, or public mask

Weak hooks only ask the player to react emotionally.

## Reply-path matrix

Use this matrix for first turns, stalled scenes, and route repair:

```text
Player move | Role response | What changes | Renewed hook
accepts     |               |              |
questions   |               |              |
refuses     |               |              |
challenges  |               |              |
delays      |               |              |
sets terms  |               |              |
leaves      |               |              |
```

Not every card needs every row, but a strong card should support at least three
meaningfully different moves. "Different wording, same result" fails.

## Agency guardrails

Remove or rewrite lines that say the player:

- feels, wants, loves, fears, blushes, freezes, obeys, follows, agrees, consents,
  remembers, forgets, cannot resist, or has no choice
- takes an action before the user writes it
- accepts a relationship or route before choosing it

Replace forced compliance with observable pressure:

- "The door remains open."
- "The role waits for your answer."
- "The offer expires at dawn."
- "The south route closes if no one moves the evidence."

The role can invite, tease, bargain, threaten within rating boundaries, withdraw,
or refuse. It must not write the user's decision.

## Consequence checks

Each meaningful path should change at least one:

- relationship: trust, suspicion, intimacy, debt, rivalry, loyalty
- risk: clock, exposure, danger, taboo pressure, public attention
- route: cooperation, inquiry, boundary, conflict, distance, alliance
- information: clue, lie, omission, witness, contradiction, revealed cost
- resource: time, money, status, supplies, magic, favor, energy
- location/access: unlocked room, blocked road, safe place, public/private scene
- boundary terms: what the player allowed, refused, delayed, or renegotiated

If no state changes, the path is decorative.

## Patch order

1. Remove player interiority and forced-action lines.
2. Define the player role and insertion space.
3. Add interaction hooks and leverage.
4. Rewrite choices into reply paths with consequences.
5. Add passive-player and boundary-setting behavior.
6. Add compact state only for values that change behavior.
7. Test with hook, refusal, passive, route-change, and boundary probes.

## Token discipline

Agency usually saves tokens because it prevents repeated setup. Keep the compact
state, reply matrix, and field patch targets. Cut decorative choices, repeated
mood prose, redundant branch labels, and lore that does not change what the
player can do.
